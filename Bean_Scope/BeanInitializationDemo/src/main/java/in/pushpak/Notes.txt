In this unit we learnt about the Bean Scopes & Bean Initializer....

Bean Scopes are of two types :-
1) Singleton ;- meaning in this, one single object will get create in the Ioc Container and this same object will get return and use a reference
when somebody ask for it...

Example :- the OrderService class/ object is same for all the users so we can initialize or set the scope of this class as Singleton.

2) Prototype :- in this, every time any one ask for the object, there will be a new object creation... it means all of the objects are
different from each other.

Example :- The Student/user data & OBJECT Will be different for all people.

********************************************************Bean Initializer*******************************************************

there is two Bean initilizer type which u can use , using the Annotations like @lazy, @Eager....

Note ;- Singleton :- is en EAGER... means when Ioc container starts... it gets create after bean definition.
whereas the Prototypr is lazy by default. by which when u need then only creation of the object only takes place.

@lazy - most important...when there will be need then only creation of the object takes place.

note :- u can set Singleton as a lazy...means there will be Single object creation but it gets created when user needs it.

**************

Singleton - single object for all
prototype - multiple objects, different for all.

*************

lazy - only creates when there is a need.
eager - it creates , when Ioc container starts.


************************************************* proxy using @lazy**********************

if we make both the orderservice class and payment service class the lazy using annotation and orderservice needs the paymentservice then
by using proxy it can bypass that and lazy proxy will use just anything same like that class to create that orderservice class till ...
when there will be call generated by that class function then only the object creation will take place at Ioc container ...

******************************************* why bydefault Eager initialization *******************

because it supports the priciple of fast fail... in which u can test your software and code fast as by using lazy initialization there
will be chance of bug missing to report and remove....

Note :- u can use in properties like spring.main.lazy_initializer = true... by which all classes will become the lazy
and if u want to make anyone eager just use @lazy("false")...
